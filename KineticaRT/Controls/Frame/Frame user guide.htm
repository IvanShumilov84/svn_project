Properties:

AddListFile: This is the name of an xml file (format below) which defines which controls and components can be added to a frame during editing. It also defines a list of referenced dlls in which these objects are found. If a full path is not specified, the SystemDirectory property is prepended to the filename.

 

AddListFile Format:

The root node is <Addables>. S-nodes must be <Add>, <Component> or <Reference> - other types are ignored.

<Add> Nodes define controls that can be added to the Frame, either in edit mode via the right-click menu or by using the Frame's Add method. Each <Add> node must have a Name attribute, which defines the 'friendly' name of the control, and a Type attribute, which is the 'Assembly Qualified Type' of the control. In all cases the type will be a string of the form 'typename, assembly', but in some cases the Version, Culture and PublicKeyToken may also be required.

<Component> nodes define components that can be added to the Frame, either in edit mode via the right-click menu, or by using the Frame's AddComponent method. Each <Component> node must have Name and Type attributes in the same way as an <Add> node.

<Reference> nodes are used when saving Panels (see below). Each <Reference> node must have an Assembly attribute, which defines the name of a dll containing an assembly.

 

Example:

<Addables>

   <Add Name="Frame" Type="KineticaRT.Controls.Frame, KineticaRT.Controls.Frame"/>

   <Component Name="Sound" Type= "KineticaRT.Logic.Message.Sound, KineticaRT.Logic.Message"/>

   <Reference Assembly= "KineticaRT.Logic.Message.dll"/>

</Addables>

 

SystemDirectory: This is a path to a directory. This is the directory in which the AddListFile and PanelName dll are sought if they do not specify a full path.

 

PanelName: This is the name of a dll file containing the current Panel object. Extensions other than '.dll' will be changed to '.dll'. If a full path is not specified, the file is relative to the path specified in the SystemDirectory property. If the specified file exists it will be loaded, and current controls will be unloaded. If the file does not exist the current controls will remain unchanged. When the Frame is saved, current controls will be saved to the file specified here. Note that save will not be available if no PanelName is specified.

 

Loading and Saving:

Saving is usually done via the edit mode right-click menu, although it can be done by calling the Frame's 'SavePanel' method. If no PanelName has been specified, saving is not possible.

A save will create a .dll file containing a Panel object with all the current controls and components in it. At the same time a corresponding .cs file will be generated which contains the source code for the dll. At load-time, if a .dll file of the relevent name cannot be found, but there is a .cs file of the same name, then the dll will be re-created from the source code. Hence changes can be made to a dll by hacking the source code, but this may easily cause the dll not to load so it is not to be recommended.

As soon as a PanelName property is specified, the file is loaded if possible. Hence care should be taken in specifying names as any changes to a Panel will be lost when a new Panel is loaded. To load something, change it and save it to a different name, make sure that the name chosen to save to does not exist or the changes will be lost.

 

Use of Referenced Assemblies list:

When a Panel is saved, the list of assemblies defined in the AddList file (henceforth called the reference list) is used by the compiler when it is creating the dll. It looks for these referenced assemblies in the application directory, and the save will fail if any assemblies in the reference list are not found, or if any assemblies are required that are not in the reference list. The latter occurs if for example the Panel contains a Dial, but the Dial assembly is not in the reference list. In most cases the reference list should cover all the assemblies required to create any addable control or component in the AddList file.

If a panel dll must be reconstructed from the .cs source file, the current reference list is used by the compiler, as it no longer has access to the one that was used when the dll was originally created. This may cause some errors if the current reference list is different to the original one.

 

Edit Mode:

Edit mode is a means of editing controls and their properties whilst a system is running.

Edit mode is entered by right-clicking on the Frame and selecting 'Enter Edit mode'.

In edit mode, most actions are done via the right-click menu, which has different options depending on whether the click was over a control or over the frame itself.

A table of control-selection appears below, but in brief: Clicking on a control will select it (grab-handles appear). Shift or control + click adds another control to those currently selected. With a control selected its properties can be viewed (right-click 'Properties' or Ctrl+Enter) and modified, or it can be moved or resized by dragging. With multiple controls selected andy common properties can be modified, or the alignment, layout and size of the controls can be adjusted together.

Undo: Undo undoes up to 10 resizing, moving, delete or add operations. It will not undo changes to control properties.

 

Components:

When a component is added, there is no visible evidence of it. To edit the properties of a component, bring up the frame's properties (right click on the frame's background), expand the 'Panel' property and double click on 'Components'. Properties of available components can now be altered. Note that because components do not in general have a Name property it is not possible to find them using the standard ObjectSearch, but they may be accessed by index in the Components collection if required.

 

Frame v Panel:

The Frame holds a Panel object, and it is within this Panel that other controls and components are actually contained. It is usually unnecessary to distinguish between the two, as a Frame always contains a single Panel object.. Note that the Frame's Panel object is replaced when a new Panel is loaded.

 

Connecting objects:

A top level Frame must have a delegate connected to its ObjectSearch event if channel names are going to be converted into their corresponding channels. In other words, if a Knob on the Frame has its source connected to 'myChannel', then it will ask its parent container (the Frame) to find the object called 'myChannel', and the Frame will pass on this request. If the Frame's ObjectSearch event is not handled, the object will never be found, and the Knob will not display its value. Note that a Frame automatically connects to the ObjectSearch events of all its children, including sub-frames, so only top-level frames must have explicit handlers.

 

Sub-Frames:

A sub-frame is a Frame contained within a Frame. As already mentioned, sub-frames are automatically connected to their parents to get ObjectSearches fulfilled.

If no AddListFile is specified in a sub-frame, it inherits that of it's Parent.

If no PanelName is specified in a sub-frame, then when the parent Frame is saved, the controls and components in the sub-frame are also saved. Conversely, if a sub-frame does have a PanelName specified, then it must be saved explicitly - it will NOT be saved automatically when its parent is saved.
