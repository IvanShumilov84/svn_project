KineticaRT Logging

Features

The KineticaRT Logging components provide logging of data from KineticaRT channels and replay of the data via the same KineticaRT channels.

Logger Component

This component writes data to and reads data from KineticaRT log files

FileName Property

This gives the file name and optional path of the file to be recorded.

ChannelNames Property

This gives a list of names of channels to be recorded.

TriggerChannel Property

The name of the channel used to trigger recording.

PreTriggerTime Property

Length in seconds of the period before the trigger event from which data should be included in the recording.

Note that this should not be set at the time of the trigger event since in this case the data may not have been collected and so cannot be logged to file.

PostTriggerTime Property

Length in seconds of the period after the trigger event has been cleared from which data should be included in the recording.

If the trigger is cleared imediately then this can be regarded as the recording time.

This may be set to +infinity.

FileFormat Property

This can be set to "Xml" or "Csv" which will log the data in XML format and CSV format respectively. CSV format is suitable for loading directly into Microsoft Excel and other applications. The XML format can also be read by Excel but would need a macro written to extract the data required into the layout required.

Note that the XML spreadsheet format as used by Excel 2003 and later is not currently supported.

Record Property

This can be set directly or set by a trigger event.

On being set, the Logger will start writing data to the log file starting at the current time minus the PreTrigger time, data will continue to be written until this property is cleared plus the PostTrigger time.

The channels recorded in the log will be those listed in the ChannelNames Property.

Performance

Since neither Windows nor .Net provide "Real Time" deterministic performance, the accurate timing of samples during recording is impossible to guarantee and will depend on processor/disk usage by other components and applications as well as hardware performance.

The maximum logging rate is 100Hz but it should be expected that some samples will be delayed slightly or even missed at this rate.  In a typical system 20Hz can be achieved fairly reliably although there is still the possiblity of interruptions due to other applications or by user interaction.
